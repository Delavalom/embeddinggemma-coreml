# EmbeddingGemma 2 → Core ML: design

**Date:** 2026-10-22
**Status:** approved in brainstorming. The founder waived a separate spec review.
**Repo:** `Delavalom/embeddinggemma-coreml`. Private until the quality gates pass, then public after one founder approval.

## 1. Goal

Ship the first Core ML conversion of Google's `google/embeddinggemma-2` that runs on the iPhone Neural Engine, and prove it matches the original. Deliverables:

1. Conversion scripts plus parity tests (public GitHub repo).
2. Converted `.mlpackage` files on Hugging Face.
3. A Swift package: `EmbeddingGemma` (model, tokenizer, preprocessing, downloader) and `EmbeddingIndex` (on-device vector search).

The first consumer is the founder's photo-cleanup app (`roll-ios`, separate spec). The package must not depend on that app.

**Out of scope:** audio and video embeddings, training or fine-tuning, Android, macOS-specific UI. macOS still runs the tests.

## 2. Facts about the source model

Checked against the Hugging Face API and `config.json` on 2026-10-22:

| Item | Value |
|---|---|
| Repo | `google/embeddinggemma-2`. Not gated, Apache-2.0, `EmbeddingGemma2Model`, `transformers 5.18.0.dev0` |
| Weights | one `model.safetensors`, BF16, 1.49 GB (about 744M params) |
| Text backbone | 24 layers, hidden 512, FFN 2048, 4 query heads, GELU-tanh. Layer pattern is 5 sliding : 1 full (layers 5/11/17/23 are full) |
| Attention shapes | sliding layers: head_dim 256, 2 KV heads, window 512, RoPE θ 1e4. Full layers: head_dim 512, 1 KV head, RoPE θ 1e6 |
| Per-layer input | `hidden_size_per_layer_input = 512`. How it is computed is **unknown until s0 inspects the weights** (see risk R4) |
| Vocab | 262,144 tokens. Special ids: image 258880, boi 255999, eoi 258882, pad 0, bos 2, eos 1 |
| Vision encoder | 16 layers, hidden 768, 12 heads, head_dim 64, patch 16, 2D axial RoPE (θ 100), 3×3 pooling of patches into soft tokens. Default 280 soft tokens (2,520 patches). Budget 70–1120 |
| Image preprocessing | convert to RGB, rescale to 0–1, **no mean/std normalization**, resize that keeps aspect ratio to the patch budget |
| Output | mean pooling over all tokens (`include_prompt: true`), projection to 768 inside the model, then L2 normalize. Matryoshka: 768 can be truncated to 512/256/128 and re-normalized |
| Precision | the model card says BF16 or FP32 only, **not FP16** |
| Prompts | query `task: search result \| query: `, document `title: none \| text: `, classification `task: classification \| query: `. Images take no prefix |

How the image token sequence is built (bos, boi, image tokens, eoi, and anything else) is **recorded by s0 from the real processor**, never guessed.

## 3. Approach

Rewrite the model in plain PyTorch, shaped for the Neural Engine, then load Google's weights and convert with `coremltools`. Rejected alternatives:

- **Tracing Hugging Face's own code:** fragile, and much of it falls off the Neural Engine.
- **Building the graph by hand in MIL:** unreadable. Kept only as a fallback for a single problem layer.

Neural Engine rules taken from Apple's `ml-ane-transformers`:
- fixed shapes;
- `(B, C, 1, S)` channels-first layout;
- per-head split attention with einsum;
- no dynamic gathers inside hot loops;
- normalization rewritten so FP16 can't overflow.

### Rules in AGENTS.md

1. Start every session with `just status`.
2. A stage only passes if its `artifacts/sN/report.json` has `"pass": true` and was produced by `just stage N` at the current git SHA. The report records `git_sha`, `inputs_sha256`, `gate_values`, `metrics`, `pass`, and `started_at` / `finished_at`.
3. Changing `gates.toml` requires a new `docs/decisions/ADR-*.md` in the same commit. CI enforces this with `scripts/check_gates_adr.py`.
4. Fixtures only come from `just stage 0`. CI checks `fixtures/MANIFEST.sha256`.
5. No weights or `.mlpackage` files in git. The `.gitignore` plus a CI size check (no file over 5 MB) enforce this.
6. Files stay under about 300 lines and have one job.
7. When a stage fails, read that stage's README "known failure modes" before changing code. Any new failure mode found gets added to it.

## 5. Stages and gates

All thresholds live in `gates.toml`. Cosine values are per fixture, and the gate is on the **minimum**, not the mean. Ranking metrics use the 200 text queries against the 200 images.

| Stage | What it does | Gate |
|---|---|---|
| **s0_reference** | Downloads the weights (revision pinned by commit SHA), runs the official `sentence-transformers` model in FP32 on CPU. Writes golden 768-d vectors, token ids, preprocessed pixel tensors and the exact image token sequence. Also lists every weight key and shape | deterministic: two runs give identical files. License recorded as Apache-2.0. Key inventory written |
| **s1_rewrite** | Our PyTorch rewrite, FP32, same inputs | min cosine ≥ 0.9999 (text and image). Strict weight load |
| **s2_coreml_fp32** | Convert at FP32, run on CPU (`.cpuOnly`) | min cosine ≥ 0.9999 |
| **s3_coreml_ane** | FP16, `.cpuAndNeuralEngine`, on this Mac's Neural Engine (M1 Pro) | min cosine ≥ 0.995, and ≥ 95% of ops placed on the Neural Engine (from `MLComputePlan`) |
| **s4_compress** | int8 weights first, then 4-bit palettization. Keep the smallest variant that passes | min cosine ≥ 0.99, recall@10 ≥ 0.95, Spearman ρ of the top-50 ≥ 0.9, full download ≤ 300 MB |
| **s5_swift** | Swift package on macOS: tokenizer, preprocessing, end-to-end vectors | token ids identical; pixel tensors max abs diff ≤ 1/255; end-to-end min cosine ≥ 0.99 against s0 |
| **s6_device** | PhotoSearchDemo on a real iPhone | records ms per image (70 and 280 budgets), ms per query, peak RSS, thermal state after 1,000 images. Gate: the report exists for ≥ 1 device; peak RSS ≤ 800 MB. Speed is recorded against the 60 ms target, not gated |
| **s7_publish** | HF upload, checksums, git tag `v1.0.0`, SwiftPM release, repo flipped to public | needs `--confirm` (given only after founder approval) |

### Fixtures

- **~200 images.** All CC0 or public domain, with the source URL and license recorded per file. Sources: Wikimedia Commons CC0 and Unsplash-style CC0 sets. Synthetic screenshots and memes are generated locally (rendered text, UI mockups), and blurry variants are made by Gaussian blur.
- **Categories:** people, pets, food, documents and receipts, screenshots, memes, landscapes, blurry, dark, near-duplicates.
- **Mixed aspect ratios** (portrait, landscape, square).
- **~200 texts:** queries the app will use ("screenshots of tweets", "blurry photos", "receipts", …) plus random sentences, and one 128-token string.

## 6. Python environments

- **`reference` group:** `transformers` installed from git main (needed for 5.18.0.dev0 support) plus `sentence-transformers>=6.1.0`. Used only by s0.
- **`convert` group:** the newest `torch` that the newest `coremltools` officially supports, plus `coremltools`, `safetensors`, `numpy`, `pydantic`, `pytest`. Used by s1–s4. Our rewrite doesn't import `transformers`.

Splitting them stops a dev build of `transformers` from forcing a torch version that `coremltools` can't convert. Each stage's `run.py` declares its group, and the `justfile` runs it with `uv run --group …`.

## 7. Model design

### Entry points

All entry points live in one multifunction `.mlpackage` with shared weights:

| Function | Input | Output |
|---|---|---|
| `embed_text_{16,32,64,128}` | `input_ids` int32 `[1,L]`, `attention_mask` `[1,L]` | `embedding` fp `[1,768]`, L2-normalized |
| `embed_image_{70,280}_{portrait,landscape,square}` | `pixels` `[1,3,H,W]`, 0–1 | `embedding` `[1,768]` |

**Image buckets.** The reference resize keeps aspect ratio, so shapes vary. We fix three aspect buckets per budget, each with a patch grid whose sides are divisible by 3 so 3×3 pooling works:
- budget 70: portrait 30×21 patches (480×336 px), landscape 21×30, near-square 24×27 patches (8×9 = 72 soft tokens), finalized in s2 against what the reference processor accepts;
- budget 280: double each side.

Swift resizes each photo into the closest bucket. s4's recall gate measures the cost of this against the reference's exact-aspect vectors. If recall fails because of bucketing, we add buckets (ADR) before relaxing anything.

**Token sequence.** The token sequence (prefix tokens, image placeholders, eoi) is fixed per function from s0's recorded processor output. Text-token embeddings for the fixed prefix and suffix tokens of image functions are baked in as constants, so image functions don't carry the 262k-row embedding table.

**Attention.** With text ≤ 128 tokens and image sequences ≤ about 290 tokens, every sliding-window layer (window 512) is effectively full attention. The rewrite still implements the mask so it stays correct if longer variants are added later.

**Attention direction.** Whether attention is bidirectional or causal is read from the reference implementation in s0 and asserted in s1.

### FP16 plan (s3)

1. `probe.py` records the max |activation| per layer and sublayer for all fixtures in FP32. Anything above about 30,000 is flagged as an overflow risk.
2. Mitigations, applied only where the probe flags them, each recorded as an ADR:
   - **(a)** RMSNorm computed as `x/s · rsqrt(mean((x/s)²)+eps/s²)` with a per-layer constant `s`;
   - **(b)** fold a constant scale-down into the residual stream, compensated in the weights;
   - **(c)** keep specific ops in FP32 through `op_selector`, accepting that they leave the Neural Engine.
3. Fallback if (a)+(b) can't reach the gate with ≥ 95% on the Neural Engine: ship a `cpuAndGPU` variant with FP32 norms, labeled in RESULTS.md. Recorded as an ADR; no founder approval needed.

### Embedding table (text functions)

262,144 × 512 ≈ 134M params is the largest single tensor. It is 4-bit palettized in s4 if the gates allow, otherwise int8. If Core ML's gather on the table blocks the Neural Engine, the lookup moves into Swift (an int8 table plus scales, memory-mapped) and the model takes `inputs_embeds`. That change is an ADR.

## 8. Swift package

`swift/Package.swift`, iOS 18 / macOS 15, Swift 6 strict concurrency.

```swift
public actor EmbeddingGemma {
  public enum Source { case huggingFace(repo: String = EmbeddingGemma.defaultRepo, revision: String), file(URL) }
  public enum ImageBudget { case auto, tokens70, tokens280 }
  public static func load(_ source: Source, budget: ImageBudget = .auto, dimensions: Int = 256) async throws -> EmbeddingGemma
  public func embed(image: CGImage) async throws -> [Float]                     // normalized, `dimensions` long
  public func embed(query: String) async throws -> [Float]                      // adds the search-query prefix
  public func embed(text: String, task: EmbeddingTask = .document) async throws -> [Float]
  public nonisolated var modelRevision: String { get }
}
public struct VectorIndex: Sendable {   // EmbeddingIndex module
  public init(url: URL, dimensions: Int, modelRevision: String) throws          // throws .revisionMismatch on stale files
  public mutating func upsert(id: String, vector: [Float]) throws
  public mutating func remove(id: String) throws
  public func search(_ query: [Float], k: Int, filter: ((String) -> Bool)? = nil) -> [(id: String, score: Float)]
  public func vector(for id: String) -> [Float]?
  public func save() throws
}
```

- **Tokenizer:** `swift-transformers` `Tokenizers`, loaded from the bundled `tokenizer.json`.
- **`.auto` budget:** 280 on A17 Pro and newer, 70 otherwise. Mapping lives in `DeviceTier.swift`.
- **`defaultRepo`:** a constant set from `HF_REPO` in the `justfile`. The Hugging Face account is confirmed at s7, before the first upload.
- **Index file:** header (magic, version, dims, modelRevision, count) + FP16 vectors + an id table. Memory-mapped; search uses `vDSP` / `BLAS` dot products. 50k × 256 must search in < 20 ms on an iPhone 12 (unit benchmark on macOS as a proxy, verified in s6).
- **ModelStore:** resumable `URLSession` background download into Application Support/EmbeddingGemma/<revision>/. SHA-256 is checked against `checksums.json` from the same HF revision. The previous revision is kept until the new one verifies.
- **Errors:** `EmbeddingGemmaError` with `.downloadFailed(underlying)`, `.checksumMismatch(file)`, `.unsupportedOS`, `.modelLoadFailed(underlying)`, `.revisionMismatch(expected, found)`, `.invalidImage`.
- **Tests:** tokenizer parity (fixtures), preprocessing parity (fixtures), end-to-end parity on macOS against s4 artifacts (skipped with a clear message if artifacts are missing), index round-trip, revision mismatch, top-k correctness against brute force.

## 9. PhotoSearchDemo

A minimal SwiftUI iOS app:
- asks for Photos access, then indexes the first N photos (default 1,000) with a progress bar;
- has a search field that shows the top 50 results;
- has a hidden **Benchmark** screen (also launchable with `-benchmark` and auto-run by `just bench-device`) that runs the s6 measurements and writes `s6_device.json` to the app's Documents folder, which `just bench-device` pulls with `devicectl`.

## 10. CI

GitHub Actions, macOS runner (the newest available image):
- `uv sync`; `pytest` (unit tests for the rewrite, metrics, report schema);
- `check_gates_adr.py`; fixture manifest check; large-file check;
- `swift build` + `swift test` (parity tests skip if artifacts are absent).

The full s0–s4 runs locally, not in CI, because the 1.5 GB weights and the conversion are too heavy. Their reports are committed under `docs/RESULTS.md` (regenerated) so the numbers are reviewable in PRs.

## 11. Risks

| # | Risk | Signal | Response |
|---|---|---|---|
| R1 | FP16 can't reach 0.995 with ≥ 95% on the Neural Engine | s3 | GPU variant (§7), ADR |
| R2 | The vision encoder's variable-shape parts don't convert | s2 | fixed buckets (already planned); add buckets if recall fails |
| R3 | Licensing | — | closed: Apache-2.0, not gated (checked 2026-10-22) |
| R4 | `hidden_size_per_layer_input` is a per-layer embedding lookup (like Gemma 3n) keyed by token id | s0 key inventory | image placeholder tokens use the recorded id. If the table is large, keep it outside Core ML like the main table |
| R5 | The vision encoder at 2,520 patches is too slow on older phones | s6 | `.auto` uses 70 tokens. Record measured numbers |
| R6 | Google ships an official Core ML version | — | parity harness compares against it. Reassess |

**Timebox:** s3 must pass, or take the R1 fallback, within 2 weeks of agent work from the first commit.
