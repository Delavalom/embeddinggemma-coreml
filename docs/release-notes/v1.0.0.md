# EmbeddingGemma 2 for Core ML, v1.0.0

The first public release. This is Google DeepMind's
[`google/embeddinggemma-2`](https://huggingface.co/google/embeddinggemma-2) (text and image embeddings in one
768-d space) as a multifunction Core ML model that runs on the Apple Neural Engine, with a Swift package to use
it. This is an unofficial conversion. It is not made or endorsed by Google.

## What is in it

- **The model** (on Hugging Face, pinned by commit in the Swift package): one `EmbeddingGemma2.mlpackage` with 14
  fixed-shape functions. Text: up to 128 tokens (`embed_text_16/32/64/128`). Images: budgets of 70 and 280 image
  tokens, five aspect buckets each. The weights are FP16 with int8 per-channel convolution weights and an int4
  per-block embedding table (`int8_table4`). `files.json` lists every file with its size and SHA-256.
- **`EmbeddingGemma`** (Swift, iOS 18+ / macOS 15+): downloads the model at the pinned commit, checks every file,
  compiles it once, then embeds text (`embed(query:)`, `embed(text:task:)`) and images (`embed(image:)`) into
  normalized vectors with Matryoshka truncation (default 256-d). The image budget is chosen per device.
- **`EmbeddingIndex`**: an exact on-disk vector index, tied to the model revision.
- **PhotoSearchDemo**: a SwiftUI app that searches the photo library by text, fully on-device. It also runs the
  device benchmark.
- **The pipeline** that produced and checked all of the above (stages s0-s7, gates in `gates.toml`, decisions in
  `docs/decisions/`).

## Accuracy, in short

Every vector is compared with the official FP32 model on 200 texts and 200 images at both budgets. The full tables
are below and in the model card. Two caveats, both recorded in decision records:

- **ADR-0006:** on the Neural Engine in FP16, two of the 400 test image vectors (i141, i161) miss the 0.995 cosine
  bar. They were accepted because they barely change retrieval recall, and keeping images on the Neural Engine is
  2.8x faster at budget 70 than the GPU.
- **ADR-0007:** compression is gated against the FP model on the same bucketed image shapes. Bucketing itself is
  gated separately at task level. The size limit was raised to 360 MB (zipped). The Swift package downloads the
  files uncompressed: about 450 MB of model plus 32 MB of tokenizer.

## Install

```swift
.package(url: "https://github.com/Delavalom/embeddinggemma-coreml", from: "1.0.0")
```

See `docs/swift-package.md` for usage, and the Hugging Face model card for Python (coremltools) usage.
