# iOS 27 Neural Engine cache: findings and decisions (2026-10-27)

Answers the handoff `2026-10-27-ios27-ane-cache-HANDOFF.md` (job 1) with the plan
`docs/superpowers/plans/2026-10-27-ios27-ane-cache-investigation.md`. Every claim cites an evidence file in
`evidence/2026-10-27-ane-cache/`. Raw data (listings, probe JSON, log archives) is in `~/egcm-evidence-raw/2026-10-27/`
on the founder's Mac, not in git. Phone: iPhone 13 Pro Max, iOS 27.0.1 (24A446). Mac: M1 Pro, macOS 26.6.2.

## The short answer

1. **Compiled functions do survive to the next launch** when the phone has free space. With ≥ 14.7 GB free, every
   function compiled in one launch loaded warm in the next (3.1–4.2 s instead of 45–130 s): 3/3 single-function rounds
   (E1a) and 16/16 functions over two 9-function rounds (E1d). No key changed between launches of one install.
2. **They are lost when iOS frees space.** The compiled files live in `Library/Caches` and are purgeable. iOS's
   CacheDelete purged them whenever true free space fell below about 2 GB after other purgeable data was gone: 3 of 3
   deliberate rounds, 0 of 4 at ≥ 2.25 GB (E1e). The morning's s6 failure (run 11) was this: our own compiles pushed
   the phone under 2 GB and iOS deleted what we had just compiled (`e2-run11-ios-purge.md`, `timeline-run11-payload-loss.md`).
3. **The key changes per install and per app update, not per launch.** It includes the compiled model's path and its
   files' inodes, not mtimes (Mac E0, 3/3 each). On the phone each fresh install and each `devicectl` update moved the
   data container, so the first launch after either compiles again (E1a, e1e-update).
4. **The `functionName` error is a failed Neural Engine compile**, reported with a misleading message. Logs show two
   causes: the compiler process killed by jetsam (3/6) or the compiler returning `Code=1` (3/6)
   (`e2-functionname-error-logs.md`). It is transient: **8 of 8 failures loaded on the immediate next try** (E1f 7/7,
   soak seed 1/1). It hits about 1 cold compile in 4–9 (E1d 4/27, E1f 7/27), 32–49 s into the load.
5. **The model itself is never lost.** Only the compiled cache is. The worst case is a slow first use after a purge,
   an install or an update: about 45–130 s per function, about 10 min for all nine, done in the background.

## Decisions and why

| Decision | Why | Where |
|---|---|---|
| Keep the 3-try load retry (`FunctionLoad.withRetries`) as the fix for the `functionName` error | 8/8 transient failures loaded on the next try; the retry's backoff and thermal wait only add margin | `swift/Sources/EmbeddingGemma/FunctionLoad.swift` |
| `prewarm` stops below 3.5 GB of true free space (`.insufficientStorage`); functions still load on first use | Purge below ~2 GB (3/3), cleanup aims for ~2.6 GB, one cold compile writes ~0.5 GB; so our own prewarm must not push the phone into the purge range, which is how run 11 lost the cache | `EmbeddingGemma.prewarmReserve`, `ModelStore.realFreeSpace` |
| Measure with `volumeAvailableCapacity`, not important-usage | Important-usage counts purgeable data, our cache included (27.5 GB vs 12.3 GB true) | `free-space-measures.md` |
| Compile in the background, one function at a time, never all at once in front of the user | Cold compiles take 45–130 s each; a launch with a cold compile peaks higher than a warm one | for Roll (next step) |
| Accept "cold once after install, update or low-storage purge" | iOS owns `Library/Caches`; no public API pins it. Re-compiling is the documented behaviour | — |
| No App Group model location for now | Might keep the key across updates (path + inodes would not move), but creating an App Group needs the Developer Portal web session (Apple ID + 2FA); updates are rare next to launches. Probe support exists: `-from group` | `scripts/probes/ios-load-probe/project.yml` comment |
| No GPU fallback for now | Not needed: the Neural Engine path works once compiled. ADR-0006 stays (GPU 2.8× slower on the Mac); phone GPU numbers were never taken (handoff job 2, skipped by the founder's call) | ADR-0006 |
